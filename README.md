# Платіжний шлюз AlliancePay для OpenCart 3

![AlliancePay Logo](https://alb.ua/_next/static/media/Alliance_logo.25cb4c66.svg)

## Огляд
Офіційний модуль платіжного шлюзу **AlliancePay** для **OpenCart 3**. Цей модуль дозволяє безперешкодно інтегрувати AlliancePay у ваш інтернет-магазин, забезпечуючи безпечний, швидкий та надійний процес оплати для ваших клієнтів.

## Основні можливості
* Безпечна обробка платежів через API AlliancePay.
* Підтримка різних валют та методів оплати Visa/Mastercard/GooglePay/ApplePay.
* Автоматична синхронізація статусів платежів (webhook / callback).
* Просте налаштування та зручний інтерфейс в адмін-панелі.
* Фіскалізація успішних платежів і повернень через Alliance Kasa.

## Вимоги
* PHP 7.4 або вище
* PHP розширення: gmp, hash, openssl, sodium
* OpenCart 3 версії [3.0.4.x]
* Активний обліковий запис мерчанта AlliancePay.

## Підпис запитів (JWS)
Запити підписуються алгоритмом **ES256**. У налаштуваннях модуля вкажіть приватний ключ **EC P-256** у PEM (PKCS#8, `-----BEGIN PRIVATE KEY-----`) та відповідний `kid`. Для вже налаштованих інсталяцій RSA-ключ продовжує працювати (RS256). Ключ іншої кривої, ніж P-256, буде відхилено з помилкою.

## Фіскалізація
Налаштування — у вкладці/секції «Фіскалізація» в налаштуваннях модуля:
* **Увімкнути фіскалізацію** — без цього запити не відправляються, блок і кнопки в замовленні приховані.
* **Автоматична фіскалізація** — чек створюється автоматично після успішного платежу та після успішного повернення. Вимкнено — лише кнопка «Фіскалізувати» у замовленні (і для платежів, і для повернень).
* Значення за замовчуванням: код податкової групи, УКТЗЕД (обов'язковий для податкових груп 2, 7, 8), акцизні марки, код одиниці виміру (за замовчуванням `0001`).

Для кожного товару ці значення можна перевизначити у вкладці «Фіскалізація» форми товару. Правило вибору — окремо для кожного поля: значення товару, інакше значення за замовчуванням.

Як це працює: запит `POST /ecom/jws/cashbox/v2/fiscalization/create` → запис у таблиці `alliancepay_fiscalization` (статуси `PENDING`/`SUCCESS`/`FAIL`, локально `NEW`/`ERROR`) → підписаний callback на `index.php?route=extension/payment/alliance_fiscalization/callback` оновлює статус, фіскальний номер і посилання на чек. Повторна відправка для `PENDING`/`SUCCESS`/`FAIL` не виконується; «Оновити статус» повторює той самий запит (ідемпотентний за `operationId`).

Фіскалізація повернень реєструється лише при увімкненій фіскалізації на момент повернення.

Типові помилки:
| Код | Причина | Що робити |
| --- | --- | --- |
| `missing_required_field` / `invalid_format` | Некоректне або відсутнє поле запиту | Перевірте поле з повідомлення (налаштування/дані товару) |
| `payment_not_found` | Операцію не знайдено | Перевірте статус платежу в Ecom |
| `original_receipt_not_found` | Для повернення немає чека покупки | Спочатку фіскалізуйте покупку |
| `541` (FAIL) | Помилка підписання на боці Kasa | Зверніться до підтримки Alliance |
